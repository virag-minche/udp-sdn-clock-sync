# Role 3 Teammate Interface & Experimentation Manual

Welcome! This interface specification gives you everything you need to execute, benchmark, and analyze the SDN Time Synchronization experiments without needing to modify the low-level controller or socket code.

---

## 1. Quick Start (Single-Command Execution)

To execute the entire experimental pipeline end-to-end automatically:
```bash
sudo bash scripts/run_all.sh
```
This script cleans stale state (`mn -c`), starts Ryu in the background, spins up the topology, launches the time server, executes clients under varying network conditions, collects logs into `results/`, and generates comparison plots.

---

## 2. Real-Time Controller REST API Control

The Ryu SDN controller hosts an HTTP REST API on `http://127.0.0.1:8080`. You can dynamically reconfigure network QoS and routing policies in real time using `curl`.

### 2.1 Switching Priority Mode (Static QoS)
Controls whether OpenFlow matches DSCP 46 packets and pushes them to Queue 1, or treats them as normal Queue 0 traffic:
* **Enable Priority Mode (QoS Active)**:
  ```bash
  curl -X POST http://127.0.0.1:8080/sdn/mode -H "Content-Type: application/json" -d '{"priority": "on"}'
  ```
* **Disable Priority Mode (Best-Effort Baseline)**:
  ```bash
  curl -X POST http://127.0.0.1:8080/sdn/mode -H "Content-Type: application/json" -d '{"priority": "off"}'
  ```

### 2.2 Switching Dynamic Congestion Mitigation Mode
Controls whether the controller automatically polls port byte utilization and injects dynamic throttling rules:
* **Enable Dynamic Mode**:
  ```bash
  curl -X POST http://127.0.0.1:8080/sdn/mode -H "Content-Type: application/json" -d '{"dynamic": "on"}'
  ```
* **Disable Dynamic Mode**:
  ```bash
  curl -X POST http://127.0.0.1:8080/sdn/mode -H "Content-Type: application/json" -d '{"dynamic": "off"}'
  ```

### 2.3 Querying Controller Telemetry & Port Status
```bash
curl -s http://127.0.0.1:8080/sdn/status | jq .
```
Returns JSON containing active path (`PRIMARY` vs `BACKUP`), current bottleneck utilization percentage, and connected client health.

## 3. Network Impairment & Dynamic Fault Injection

You can introduce bandwidth limits, delay, loss, and link failures at runtime either through the Mininet CLI or direct Linux Traffic Control (`tc`) calls.

### 3.1 Changing Bandwidth, Delay, and Loss at Runtime
#### Method A: Inside the Interactive Mininet CLI
In the Mininet interactive prompt:
```bash
# Adjust bottleneck link s1 <-> s2 delay to 25ms and loss to 5%
mininet> py net.configLinkStatus('s1', 's2', 'up')
mininet> py s1.connectionsTo(s2)[0][0].config(delay='25ms', loss=5)
```

#### Method B: Direct Linux `tc` Command (from Linux Terminal)
Identify the primary bottleneck interface (e.g., `s1-eth5`):
```bash
# Change propagation delay to 20ms and jitter to 5ms
sudo tc qdisc change dev s1-eth5 parent 1:1 handle 10: netem delay 20ms 5ms

# Inject 3% random packet loss
sudo tc qdisc change dev s1-eth5 parent 1:1 handle 10: netem loss 3%

# Restore default configuration (5ms delay, 0% loss)
sudo tc qdisc change dev s1-eth5 parent 1:1 handle 10: netem delay 5ms
```

### 3.2 Simulating Physical Link Failure & Failover
To simulate an abrupt fiber cut on the primary path:
* **Trigger Link Down**:
  ```bash
  mininet> link s1 s2 down
  ```
  *Observed Effect*: Controller receives OpenFlow `PortStatus` down event, reroutes active flows to the backup link (15ms delay path), and client synchronization continues seamlessly.
* **Restore Link Up**:
  ```bash
  mininet> link s1 s2 up
  ```
  *Observed Effect*: Controller debounces for 2 seconds, restores primary flows to `s1-eth5`, and client delay returns to 5ms.

## 4. Log Files and Telemetry Data Structures

All experiment metrics are automatically logged into the `results/` folder as standard CSV files.

### 4.1 Client Synchronization Logs: `results/client_<id>.csv`
Generated by each synchronization client node:

| Column Name | Data Type | Meaning / Unit |
| :--- | :--- | :--- |
| `timestamp` | Float | Unix timestamp when the sync measurement finished (seconds). |
| `cycle` | Integer | Monotonically increasing sync iteration index (1, 2, 3...). |
| `raw_offset` | Float | Calculated clock offset $\theta = \frac{(T_2 - T_1) + (T_3 - T_4)}{2}$ (seconds). |
| `filtered_offset`| Float | Internal clock offset after applying the servo gain filter (seconds). |
| `rtt` | Float | Round-trip transit delay $\delta = (T_4 - T_1) - (T_3 - T_2)$ (seconds). |
| `clock_time` | Float | Client's simulated local time right after adjustment (seconds). |
| `reference_time`| Float | Reference server time at the matching instant (seconds). |
| `error_ms` | Float | True absolute synchronization error $\|T_{\text{client}} - T_{\text{server}}\|$ (milliseconds). |

### 4.2 Controller Global Log: `results/controller_log.csv`
Captures controller state transitions and decisions:

| Column Name | Data Type | Meaning |
| :--- | :--- | :--- |
| `timestamp` | Float | Unix timestamp of the recorded controller event. |
| `event_type` | String | Event classification: `CONGESTION_START`, `CONGESTION_END`, `LINK_DOWN`, `LINK_UP`. |
| `active_path` | String | Currently routed topology path: `PRIMARY` or `BACKUP`. |
| `utilization_pct`| Float | Calculated link utilization percentage at event time. |
| `rules_installed`| Integer | Total active flow entries currently enforced on switches. |

### 4.3 Port Statistics Log: `results/port_stats.csv`
High-resolution switch datapath telemetry recorded once per second:

| Column Name | Data Type | Meaning |
| :--- | :--- | :--- |
| `timestamp` | Float | Unix timestamp of the polling cycle. |
| `dpid` | String | Switch datapath ID (`s1` = `0000000000000001`, `s2` = `0000000000000002`). |
| `port_no` | Integer | Switch port number inspected (Port 5 = s1 bottleneck, Port 3 = s2 bottleneck). |
| `tx_packets` | Integer | Total packets transmitted through the port. |
| `tx_bytes` | Integer | Total bytes transmitted through the port. |
| `tx_drops` | Integer | Packets dropped at output queues due to buffer overflow. |
| `utilization` | Float | Calculated bandwidth utilization percentage over the last 1.0 second. |

## 5. Exact Commands for Core Experiments (E3, E4, E5)

Follow these exact sequences to produce publication-grade evaluation data for 3, 5, and 10 client configurations.

### 5.1 Experiment E3: Congestion WITHOUT SDN Priority (Baseline)
Demonstrates clock degradation under bulk load when no QoS is applied.
```bash
# 1. Clean previous state
sudo mn -c

# 2. Start Ryu controller with priority turned OFF
source ~/ryu-env/bin/activate
ryu-manager sdn/controller.py &
sleep 2
curl -X POST http://127.0.0.1:8080/sdn/mode -d '{"priority": "off", "dynamic": "off"}'

# 3. Run automated E3 benchmark for N=3, 5, and 10 clients
# For 3 clients:
python3 experiments/runner.py --experiment E3 --clients 3 --duration 60 --load 12M --output results/E3_3clients

# For 5 clients:
python3 experiments/runner.py --experiment E3 --clients 5 --duration 60 --load 12M --output results/E3_5clients

# For 10 clients:
python3 experiments/runner.py --experiment E3 --clients 10 --duration 60 --load 12M --output results/E3_10clients
```

### 5.2 Experiment E4: Congestion WITH SDN Priority (DSCP 46 Queuing)
Demonstrates clock stability and buffer-bloat bypass with static Queue 1 allocation.
```bash
# 1. Enable Priority Mode via REST
curl -X POST http://127.0.0.1:8080/sdn/mode -d '{"priority": "on", "dynamic": "off"}'

# 2. Run automated E4 benchmark for N=3, 5, and 10 clients
# For 3 clients:
python3 experiments/runner.py --experiment E4 --clients 3 --duration 60 --load 12M --output results/E4_3clients

# For 5 clients:
python3 experiments/runner.py --experiment E4 --clients 5 --duration 60 --load 12M --output results/E4_5clients

# For 10 clients:
python3 experiments/runner.py --experiment E4 --clients 10 --duration 60 --load 12M --output results/E4_10clients
```

### 5.3 Experiment E5: Dynamic Mitigation & Link Failover
Demonstrates automated hysteresis throttle and active link failover under primary link breakdown.
```bash
# 1. Enable Dynamic Mode
curl -X POST http://127.0.0.1:8080/sdn/mode -d '{"priority": "on", "dynamic": "on"}'

# 2. Run automated E5 failover benchmark (Injects link drop at t=25s, recovers at t=45s)
python3 experiments/runner.py --experiment E5 --clients 3 --duration 70 --load 12M --failover --output results/E5_failover
```

## 6. How to Reproduce & Plot Comparison Graphs

Once CSV files are generated in `results/`, run the visualization script to produce side-by-side comparative analysis graphs:

```bash
# Generate convergence, offset jitter, and RTT CDF graphs
python3 scripts/plot_results.py --input-dir results/ --output-dir results/plots/
```

This generates three high-resolution graphs:
1. `convergence_comparison.png`: Comparing synchronization convergence curves for E3 vs. E4.
2. `offset_jitter_boxplot.png`: Statistical variance and offset dispersion across 3, 5, and 10 clients.
3. `failover_timeline.png`: Continuous offset and RTT timeline during link failure and recovery.
